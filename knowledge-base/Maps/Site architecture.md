# Site architecture

The studio's website is a static site of hand-written HTML, CSS and vanilla JavaScript with no framework and no runtime dependency; a few pages and regions are generated by small Node scripts, and only the files listed in `scripts/site.mjs` are ever published (README.md › This repository — the landing page). This map shows which pages exist, how `index.html` and `assets/app.js` are put together, and the small scripts that tie the pages to each other. Start with the page table, then read the `index.html` anatomy; language handling has its own map, [[Languages and RTL]].

## The pages

|---|---|---|---|---|
| `index.html` | The landing page | FR baked in, EN and AR applied by `app.js` | `assets/app.js`, `assets/carry.js` (both deferred) | Hand-written; its French copy, voices region and legal footer markers are written by generators |

## index.html anatomy

### Head

- One inline script runs before the stylesheets: it picks the theme and the language, sets `data-theme`, `lang` and `dir` on `<html>`, sets the canonical URL, writes the font preloads and exposes `NUMIDEA_WA` (the WhatsApp number) and `NUMIDEA_LANG` (index.html › 87). This is the [[Head bootstrap  pre-paint resolver]].
- Then three stylesheets in a fixed order: `fonts.css`, `themes.css` (the theme blocks), `styles.css` (layout and components, which only reads the tokens) (index.html › 170). Themes are covered in [[Themes and tokens]].
- One JSON-LD block describes the studio as a `ProfessionalService` (index.html › 37). A second one, the FAQ as a `FAQPage`, is not in the head but at the end of the body, and `scripts/build-fr.mjs` writes it from `I18N.fr` (index.html › 1299–1301). See [[Studio Structured Data (ProfessionalService JSON-LD)]] and [[FAQ Structured Data (ld-faq)]].

## assets/app.js, part by part

`app.js` is one IIFE with no dependencies that honours `prefers-reduced-motion` (assets/app.js › 1). Its parts, in file order:

| Part | Locator | What it does |
|---|---|---|
| `I18N` | i18n dictionary | The `fr`, `en` and `ar` dictionaries; `ar` sets `dir: 'rtl'` (assets/app.js › i18n dictionary) |
| `EXTRA` | Services Catalog + Trust strip strings | More strings, merged into `I18N` per language (assets/app.js › EXTRA) |
| `ESTIMATE` | estimator model | Pure figures and arithmetic, including `PRICE_MODEL`, so a script can test it without a page (assets/app.js › estimator model). Prices are in [[Pricing and market]] |
| `applyLang()` | after `ESTIMATE` | Swaps every translated node and attribute, the title, meta description and both JSON-LD blocks (assets/app.js › applyLang) |
| count-up | count-up | The animated counters (assets/app.js › count-up) |
| DOM ready | DOM ready | Language switch, theme switcher, scroll progress, reveal-on-scroll, ambient parallax, hero plate, mobile menu, legacy `#/work` redirect, founder résumé accordion, contact form (assets/app.js › DOM ready) |
| 12 | project estimator | Reads the estimator's controls and writes the result; plural forms per language (assets/app.js › 12 · project estimator) |
| 12a | display currency | Converts dinar prices to € or $ for display only (assets/app.js › 12a · display currency) |
| 13 | WhatsApp | Builds `wa.me` links from `NUMIDEA_WA`; holds [[leadSource()]] and `refTag()` (assets/app.js › 13 · WhatsApp) |
| — | phone contact bar | The two-button bar on phones (assets/app.js › phone contact bar) |

## Contact and lead flow

1. With JavaScript off, the form posts to a `mailto:` and the browser checks required fields; with it, `app.js` validates and shows its own messages (assets/app.js › contact form).
2. If `NUMIDEA_SUPABASE_URL` and `NUMIDEA_SUPABASE_KEY` are set, the lead is also sent, best effort, to a Supabase `leads` table (assets/app.js › contact form). Both are empty strings today, so this step does nothing (index.html › 1294). The owner keeps it off on purpose (OWNER-CONTENT.md › 11).
3. The mail client opens pre-filled to the site's one address, with a "Source" line from `leadSource()` (`?ref=`, `utm_*`, and whether `fbclid` or `gclid` is present) (assets/app.js › contact form; BRAND.md › Lead source).
4. WhatsApp links append only the `ref` code, as `[ref]` (assets/app.js › 13 · WhatsApp).

Nothing is stored and there are no cookies or analytics (README.md › Features). See [[Lead source without tracking]], [[Contact form flow (validation - optional Supabase insert - mailto)]], [[Supabase lead store (off on purpose)]] and [[_COMMUNITY_i18n and Contact Flow]].

## 404.html

- GitHub Pages serves this page for any missing URL at any depth, so its head script recomputes the site root (the repository subpath on `*.github.io`, `/` elsewhere) and rewrites its asset links before first paint (404.html › 64). See [[Site-root recomputation for the GitHub Pages 404]].
- It follows the visitor's stored theme and language, with `?lang=` first; all three languages are always in the markup, and `html[lang]` picks the button label, so no text is swapped after paint (404.html › 64).

## Generated parts

| Output | Generator | Command |
|---|---|---|
| French baked into `index.html`, its title, description and FAQ JSON-LD | `scripts/build-fr.mjs` | `npm run build` |
| `scene/index.html` | `scripts/build-scene.mjs` from `scripts/scene-data.mjs` | `npm run scene` or `npm run build` |

Sources: package.json › scripts; README.md › Commands; BRAND.md › Project sheets (scene/). `check.mjs` fails when a generated page differs from its generator's output (scripts/check.mjs › 7). The gates are in [[Build and gates]]; the sheets in [[Project sheets]]; `hub/` and `workspacehq/` in [[WorkspaceHQ and hub]]; the screenshot, logo and share-image scripts in [[Captures and image tools]].

- **The legal page.** `scripts/build-legal.mjs` builds `legal/index.html` from `LEGAL` in `scripts/legal-data.mjs` only when every owner field is set; otherwise it writes nothing and empties the footer and contact-form marker regions in `index.html` (scripts/build-legal.mjs › header). Every `null` in the data is a fact only the owner can give (scripts/legal-data.mjs › header); they are listed in [[Open owner items]].
- Once the last field is filled, `npm run build` writes the page and it joins the deploy set, the sitemap and every gate automatically (scripts/legal-data.mjs › header; scripts/site.mjs › LEGAL_PUBLISHED).
- `node scripts/build-legal.mjs --preview` writes `legal-preview/` with the gaps marked; it is git-ignored and never deployed (scripts/build-legal.mjs › header).
