# Architecture & Repository Map

*Audited 2026-07-31 · commit `a9fd6da` · branch `claude/numidea-labs-landing-c4jokc`*

## What this system is

A **zero-dependency trilingual static marketing site** for Numidea Labs (software
studio, Bordj Bou Arréridj, DZ). Hand-written HTML/CSS/vanilla JS. No framework,
no build step, no bundler — `index.html` opens and runs. Two runtime
`devDependencies` (`playwright`, `sharp`) exist only for the offline
screenshot-capture pipeline, never shipped to the browser.

**Deploy:** every push to `claude/numidea-labs-landing-c4jokc` publishes the repo
root to GitHub Pages via `.github/workflows/pages.yml` (~60–90 s).
`vercel.json` additionally makes the repo import-ready for Vercel (clean URLs,
immutable asset caching, security headers) — not yet connected.

## Data flow & critical paths

```
visitor → index.html
  ├─ styles.css?v=<stamp>   (cache-busted; bump on every content change)
  ├─ app.js?v=<stamp>
  │    ├─ localStorage: numidea-lang / numidea-theme   (shared with scene/)
  │    ├─ I18N + EXTRA dicts → applyLang() rewrites [data-i18n] innerHTML
  │    ├─ PROJECTS[] → explorer modal (hash router #/work/<slug>)
  │    └─ contact form → (optional Supabase POST /rest/v1/leads, config-gated,
  │        fails silent) → mailto: handoff → success state
  ├─ hub/   (isolated: own CSS/JS/theme key void-theme)
  └─ scene/ (reads numidea-* keys; own CSS/JS)
```

**Conventions that must hold** (verified in this audit, enforce on every change):

1. Every i18n key appears **exactly 3×** in `app.js` (fr/en/ar). ✔ balanced.
2. Every `data-i18n*` attribute in HTML resolves to a dictionary key. ✔ no orphans.
3. Every asset reference carries `?v=<stamp>`; bump **all pages** on any change.
4. New features must no-op gracefully when config is absent (Supabase pattern).
5. Statuses stay honest: no fake screenshots, `soon`/pending states are explicit.

## Known risks

- **Single-file JS/CSS growth** — at ~900 lines each, still navigable; if the
  explorer or services catalog grows further, split by concern (i18n dict → JSON?)
  only when pain is real. No framework migration is warranted.
- **localStorage coupling** between `/` and `/scene/` is implicit contract —
  documented here; breakage would be silent (falls back to fr/arcanum).
- **The deploy branch is a `claude/…` working branch** and is also the Pages
  source and de-facto default. Renaming it to `main` would be cosmetic but
  requires updating `pages.yml` + Pages settings + Vercel production branch
  in the same change.
